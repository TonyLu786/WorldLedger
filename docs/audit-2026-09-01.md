# Audit, 2026-09-01

Eight parallel reviews of this repository, one per dimension: Minecraft domain
correctness, the Fabric adapter, security and privacy, test strategy, end-to-end
performance, Go correctness and resource safety, documentation truthfulness, and
build, release and CI. Each was told to prove what it could and to mark what it
could not, and to report what it checked and found sound as well as what it
found wrong.

Sixteen of the findings below were re-verified independently before being
written down, and are marked **verified**. The rest carry the reviewing
reader's own evidence, which is cited.

Twelve findings are fixed and that work is in this repository's history. The
rest are open, and the ones that change what the program means rather than
correcting a defect are open deliberately: they are decisions, and a decision
taken while clearing a list is a decision nobody made.

## What the audit says about the codebase as a whole

Three things came out of comparing the eight reports that no single finding
shows on its own.

**Local reasoning is careful and cross-boundary assumptions are not checked.**
The three most damaging defects each have a comment beside them that states the
hazard correctly, and an implementation on the other side of a boundary that
walks into it. `anvil.DataVersion26_2` warns that stamping a version the target
world does not use silently runs data fixers over data that was never in an
older format, and the CLI defaults to it whatever release the observation came
from. `readCollectionCount` says an untrusted count can never drive a large
speculative allocation, which is true of the allocation it names and false of
the memory that matters, because one input byte becomes a 152-byte value.
`internal/spool` renames an imported bundle rather than deleting it and notes
that the new name is invisible to the adapter, and the adapter counts every file
it finds. None of these is carelessness. Each half is right about what it can
see.

**Invariants are well defended; drivers are not.** Twenty-one hand-written
mutations were run against the suite. The fifteen that were killed are all
invariants: identity derivation, canonical encoding, the selection algorithm,
lock semantics, region layout, redaction filtering, the cross-platform gate. The
five that survived are all drivers: HTTP handlers, CLI command entry points, and
the loop inside seed recovery. Measured coverage agrees, at 6.9% for the desktop
API package and 12.1% for `cmd/worldledger`. This is the shape of a project
whose core is trustworthy and whose edges repeatedly say things the code does
not do, and it explains why documentation drift keeps being the largest category
by count.

**Honest unknowns holds at chunk granularity and not below it.** A section
inside a chunk's declared shape whose blocks were never observed is not written,
which is correct and deliberate, and Minecraft fills it with air on load.
Nothing counts it and nothing reports it. The property this project is built on
is true of the file format and not of what somebody sees.

### 1. Opening an archive could delete a file outside it (verified)

`recoverPurges` validated the journal's observation ids, with a comment saying a
journal is read off disk and cannot be trusted for having been written by us,
and passed its object references straight to `os.Remove`. `cas.Store.Path`
checked that a digest had four characters and then joined it onto the store
root, so a reference of `../../../../victim.txt` resolved four levels above the
archive. Every command opens the archive and opening it replays the journal.

Reproduced: that digest resolves to `C:\victim.txt`, and a test confirmed a file
outside the archive was removed by `Open`.

The store now refuses to build a path from anything that is not sixty-four
lowercase hexadecimal characters, so `Path`, `Open`, `Remove` and `Verify` fail
closed together rather than each caller having to remember. The journal check
says the same thing where the reason for it is legible.

### 2. Canonical NBT decode amplified 152x with no aggregate bound (verified)

`readCollectionCount` bounds a declared count against the bytes remaining, which
is correct for the speculative allocation it names. The smallest input that
produces an NBT value is one byte and the value is 152 bytes, so a mebibyte of
`TAG_Byte` list became 152 MiB; and `DecodeBlockEntities` chains one NBT per
block entity out of a single component, bounded only by the 64 MiB component
limit, so the ceiling was roughly 9.5 GiB. Measured by the reader at 40 MiB in
against 6.1 GiB retained.

Nothing decodes on the way in. A transfer bundle and a capture bundle are both
accepted on digest alone, so hostile bytes sit in the object store until
somebody exports a world, which for a desktop user is a button.

Decoding now spends from one budget shared across every nested payload in a
component, bounding a component to about 80 MiB of materialised NBT.

### 3 and 4. Two ways a peer's file broke the tool (verified)

`--server EXAMPLE.ORG` found chunks through `coverage` and produced an empty
fingerprint, with the root of an empty tree and exit 0, because the filter was
compared raw against names that are always normalized on disk. That is
indistinguishable from an archive holding nothing, and handing it to a peer asks
them to send everything. Separately, a line that is not empty but holds no
fields indexed past the end of a slice, so a file a peer supplied ended the
program with a stack trace and exit 2.

### 5 and 6. Capture stopped permanently for anyone using the window (verified)

The budget added up every file under the spool. The desktop keeps a bundle after
importing it, renaming it rather than deleting it so that a window never
destroys somebody's only copy, and `internal/spool` records that reasoning and
adds that the new name is invisible to the adapter. It was not. A contributor
who imported every evening still reached the 4 GiB ceiling, and when it tripped
capture stopped for that client session and every session after it, with a
notice telling them to import and clear the spool: what they had been doing.
Quarantined bundles counted too, and nothing on either side of the boundary ever
removes those.

Separately, `Files.walk` aborts when a subtree vanishes mid-walk, which is what
running `ingest-spool` while the client is connected looks like. The resulting
unchecked exception escaped the budget check and reached the writer's generic
failure handler rather than its full-spool handling, so capture continued and
the chunk being written was lost.

### 7 and 8. Both documented paths could not run (verified)

The README's sixth step exports into a world Minecraft has just created, and
Minecraft has already written the region file the spawn sits in, so the export
refuses unless told it may write there. The flag that does that appeared in no
document in the repository. The window sets it unconditionally, which is why
only somebody following the written path would meet this. The site had the same
gap and also skipped declaring a publication policy, which export requires, so
its three-line recipe exited 1 on the step the page exists to demonstrate.

Both were then run as written, which is how the first correction to the site was
caught using a flag that does not exist.

### 9 and 10. The release workflow (verified)

The note about being pinned to one Minecraft release, and about reading
`NOTICE`, was indented under `body_path`. YAML folded it into the value, so the
path stopped being a path; a parser confirms `body_path` held a three-line
string. The preceding step, which extracts this version's notes from the
changelog and fails if they do not match the tag, was computed and discarded.
Separately, `contents: write` at workflow scope put a repository-write token in
reach of the Gradle job, which downloads and executes third-party build plugins
with no dependency verification.

### 11 and 12. Two things that were simply wrong (verified)

The desktop labelled `StatusUnknown` as recorded but unreadable. It means the
opposite: the observations are fine and none of them predate the moment being
asked for. The count is zero on an export of now, so the only people who ever
saw it were the ones using the feature the application is built around.
`docs/status.md` gave 55 objects twice and 52 once for the same session; the
committed fingerprint reference has 55 component lines.

## Open, and needing a decision rather than a fix

These change what the program means. Each should become a decision record.

**The export stamps DataVersion 4903 whatever release the observation came
from** (verified). `--data-version` defaults to the pinned 26.2 constant and its
help text says it matches the captured release, which it does not enforce. The
reader confirmed from the game's own bytecode that there is no
newer-than-current guard in `ChunkStorage` and that the data fixer applies
nothing when asked to upgrade from a version above the target, so every fixer
between the two releases is silently skipped. The decision is what the default
should be: the version implied by the observations' protocol string, resolved
through a shipped profile, and whether disagreement among observations should
refuse rather than pick.

**Honest unknowns does not hold below chunk granularity** (verified). A section
inside the declared shape with no observed blocks is skipped, correctly, and
vanilla fills it with air. `ExportReport` has no field for it. The decision is
whether to count and surface these the way `Summary.Unknown` is surfaced, which
changes what an export tells somebody about a world they are about to open.

**Corroboration counts votes without regard to when they were cast.** Already
written up as [ADR 0003](decisions/0003-corroboration-and-time.md) and still
open.

**The desktop status poll walks the kept spool on every screen.** Measured at
5.399 s of a 5.851 s poll against a real spool of 608 kept bundles, growing
linearly with bundles kept and independent of archive size. The obvious fix is
to stop computing the spool's size on the status path, but that size is on the
play screen deliberately, so removing it removes something somebody added on
purpose. The decision is where the number comes from, not whether the walk
belongs on the poll.

## Closed since this was written

This is a record of what was found on 2026-09-01, and the two lists below say
what was open on that day. They have not been rewritten, because a dated audit
that gets edited to stay true stops being evidence of anything. What has been
closed since is recorded here instead, with the numbers as they turned out
rather than as they were projected.

**Export holding the whole decoded world** is fixed. A dimension is written one
region file at a time, so the peak is one region file's worth, around 210 MiB,
whether the export is a thousand chunks or a million. The 205 KiB per chunk
above was right; the factor was not a useful way to say it, and an export
covering three region files went from 320 MiB to 155 while one covering a single
region saves nothing at all.

**convert still held the whole dimension** after that fix, which was recorded in
the code at the time as a real difference rather than an oversight, on the
grounds that the data version came out of translating everything. That reason
was wrong: the data version comes from the target profile and is known before a
chunk is read. What is genuinely whole-dimension is the report policy's promise
to write nothing if anything is unrepresentable, so under that policy the
translation now runs once to decide and once to write, and under the two
policies that cannot refuse it runs once. The deciding pass measures at about a
fifth of the writing pass with nothing to translate.

**Importing one full-height chunk at 212 ms** is improved, not by the factor
projected here. Components are stored four at a time; measured over twelve
bundles of fifty components, 276 ms per bundle became 189. This audit projected
212 down to about 50 and that was wrong: what overlaps is the reading and the
hashing, while the rename and the forcing to disk are one volume's metadata and
queue there however many callers ask at once.

**`send --out` pointing at the archive**, **`--x`, `--z` and `--data-version`
truncating to int32**, and **`Region.Bytes` allocating seven times what it
produces** are all fixed. The last is at 1.00x and held there by a test.

**The surviving mutation named under Test coverage** -- deleting the consent
gate that refuses to build a world from a server nobody has declared, and
finding the whole desktop suite still green -- is closed. That package went from
6.9% covered with every handler at zero to 47.4% with no handler at zero.
Writing those tests turned up something the audit had not: the status route,
which the page loads on every screen change, walked every capture bundle kept
after import to report how much disk they use. On the machine it was found on
that was 608 directories and 4.5 seconds of a window standing still after a
click, growing for as long as somebody plays. It is 266 ms on the first load and
4 ms after.

**convert had no test of any kind**, which this audit did not say and should
have. It has some now.

Everything below stands unless it appears above.

## Open defects, not yet fixed

Ranked by impact times confidence.

**Export holds the whole decoded world in memory before writing anything.**
Measured at 206 KiB per chunk after `Prepare`, exactly linear over two runs, with
export peaking at a further 234 to 245 KiB per chunk. A hundred thousand chunks
extrapolates to 20.6 GiB resident and about 44 GiB peak. Grouping by region file
and looping bounds peak at about 206 MiB regardless of archive size.

**Importing one full-height chunk costs 212 ms, all of it in the object store,**
at 4.24 ms per component across 50 components. A 300-chunk session is 64 s; a
hundred thousand fresh observations is 5.9 hours. The 50 `Put` calls in one
bundle are independent and the store deliberately takes no archive lock, so a
worker pool would take it to about 50 ms. This corrects an earlier figure of 11
to 12 ms per observation measured here on single-component observations; the
difference is entirely component count.

**Quitting from inside a world freezes the client for up to 15 seconds.**
Fabric's client-stopping event is injected before `level.disconnect()`, so the
final-flush path runs with the level still loaded: a 10 s flush budget plus a 5 s
busy-wait on the game thread, plus snapshot time the budget does not bound.

**`flushAll` keeps building whole snapshots after its deadline and discards
them,** so the 10 s and 1 s budgets are not bounds. A retried chunk is re-claimed
on the very next tick rather than after the coalescing window, so a backlog burns
a full snapshot per tick, and a deterministically failing chunk logs a stack
trace every tick indefinitely.

**`enqueued` counts hand-offs, not bundles on disk.** An unwritable spool path
reports a session that captured thousands of chunks with zero bundles written,
because that failure is not a full spool and nothing else is counted.

**`SpoolBudget.measure()` walks the whole spool on the writer thread.** Measured
at 16.8 to 21.2 s for 2,000 bundles, which is 102,000 files. The prefix filter
added above cuts what it walks; the shape, one whole-spool walk per 32 bundles,
remains. A running total seeded once and adjusted per write removes it. This
corrects an earlier assessment here that rated the walk low severity on an
amortisation argument that counted bundles rather than files.

**Peer-supplied manifests and fingerprints are read with no size cap,** while
every other untrusted input in the codebase is capped.

**`send --out` pointing at the archive corrupts it and exits 0.**
`internal/bundle` has exactly this guard; the send path has none.

**`--x`, `--z` and `--data-version` are parsed as `int` and truncated to
`int32`.** A coordinate above the range is stored at a different chunk and its
identity derived from the truncated value.

**Region files vanilla repairs abort the whole export.** Vanilla zeroes a slot
whose length is not positive or whose range runs past the end, and loads the
file; `Adopt` refuses, with an error saying data would be lost when the slot
holds nothing, and no flag proceeds.

**Chunks needing 256 sectors or more cannot be exported.** Vanilla's external
`.mcc` file is not implemented. `Adopt` does correctly preserve an existing
external stub.

**`Region.Bytes` allocates seven times the region it produces,** 111.6 MiB for a
16.0 MiB region. **`coverage --map`** spends 6.5 s and 1.9 GiB drawing 4,000
coloured pixels at a 4,000-chunk span, because the background is filled one pixel
at a time.

**`transfer.Receive` re-hashes every component twice** and takes the archive lock
twice per record. Skipping the second verification for digests the same bundle
just stored saves a measured 32%.

**The capture adapter refuses dimensions taller than 2032 blocks;** vanilla
allows 4064. **`Shape.MaxSectionY` overflows,** and the Go core has no
`section_count` bound while the Java adapter caps at 127, so the two reference
implementations disagree about what a valid shape is.

**Five flags exist and appear in no usage string,** two of them documented in the
README or named by an error message that tells the reader to pass them.
**`corpus` is named as a release gate in three shipped documents** and is absent
from `worldledger help`. **The README calls redactions reversible** and never
names `redact withdraw`, while `redact set` signposts only the destructive
`purge`. **`docs/milestone-java-capture.md` says the milestone is incomplete**
and cites 50 bundles, where the roadmap and status say met and the committed
reference holds 158. **`adapters/fabric/README.md` says configuration needs a
restart** and a reload command exists. **`spec/capture-bundle-v1.md` omits that
unknown manifest fields are hard-rejected** and hints the opposite, which is a
trap for a second adapter implementer.

**`verify --window` defaults to 10 s** while everything that builds a world uses
30 s, so the diagnostic disagrees with the exporter, silently, and no document
states either number.

## Test coverage

Twenty-one mutations: fifteen killed, five survived, and one
semantically-identical control which survived as it should, confirming the
harness produces no false kills.

Killed, and recorded because they are evidence of strength: identity losing
sub-second precision, `StateDigest` no longer binding component size, the
corroboration threshold, the conflict and superseded boundary, `regionSlot`
transposing X and Z, an Anvil frame length off by one, `ChunkBounds` treating its
maximum as exclusive, transfer skipping `ValidateStored`, purge journal replay
becoming a no-op, purge id validation removed, the archive lock downgraded from
exclusive to shared, the canonical palette sort reversed, reconstruction applying
an emptied redaction set, and the cross-platform fingerprint gate returning
success both on a disagreement and on no shared chunks.

Survived, and open: every desktop HTTP handler is uncovered, so deleting the
consent gate that refuses to export a world nobody has declared leaves the suite
green; one of 25 CLI commands is executed by any test; `seed.Search` is uncovered
in both modules, so both deleting its consent gate and making it return every
integer in range as a candidate survive; the transfer check that a declared id
matches its file's content is untested; and zeroing the timestamps of adopted
region chunks survives, so an export into a real world can blank the game's
last-write times for every chunk it did not write.

Also open. **Windows locking and atomic replacement have never been
race-detected anywhere,** because `-race` runs on Linux only, which compiles the
`flock` implementation instead, and the Windows job runs without it. **The live
game test never exercises time travel:** `corpus` requires seven shapes, all
spatial, and the committed reference holds 158 states over 157 chunks, so the
end-to-end gate for this project's stated differentiator has a temporal depth of
one incidental chunk. **`docs/test-strategy.md` lists an interrupted-import test
that does not exist.**

## What was checked and found sound

Recorded because a review that lists only faults misrepresents what it looked
at.

The canonical encoding was verified against the pinned game's own bytecode:
index packing matches vanilla for every palette size including the
global-palette cases, the region layout and slot arithmetic are exact, the chunk
NBT key set is what the game reads back, the capture axis order matches the
game's index function, property values use the game's canonical names, and
waterlogging survives capture, canonicalisation, translation and Anvil writing
intact. The blockstates-derived block profile cross-checks clean against block
tags and loot tables, with zero misses.

No Minecraft object crosses to the writer thread; every mixin callback is
provably on the client thread; the bootstrap and join handshake cannot double-
join or apply a join to a stale connection; the spool's cross-process lock is
correct. Bundle path handling rejects traversal, absolute and volume-qualified
paths, NTFS alternate data streams and per-element symlinks, with a containment
re-check after opening. Transfer validates digests before every path join and
re-derives every identity from content. The desktop server's Host allow-list,
refused preflight, header-only token and constant-time comparison hold up.
Attestation signatures cannot be replayed onto another record. The seed-recovery
gate is real. Redactions are applied on both share paths. Every archive lock is
released on every path. The root module genuinely has no external dependencies.
Every workflow action is pinned to a commit, no workflow is fork-reachable with
a secret, and the release binaries are byte-reproducible.

## Method

Eight reviews ran in parallel against a working tree that was not modified; each
was told to work in a copy and to change nothing in the repository. The mutation
testing was done in a throwaway copy. Every quantitative claim above was
produced by running something, and the extrapolations say so where they are
extrapolations. Where a reader could not establish something, it is marked as
inference here as it was there.
